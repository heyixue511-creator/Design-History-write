# 框架成果与审查要求

本文件供制定、修改或审查实际框架时按需读取。四类内容表达不同层级的判断，不要求建立四套重复文档。

## 成果位置

| 成果 | 现行或建议位置 | 保存原则 |
| --- | --- | --- |
| 全书定位 | `03-教材框架/00_书籍定位.md` | 沿用现有文件，仅在任务需要且授权范围内更新 |
| 全书目录与框架论证 | `03-教材框架/01_全书框架.md` | 同一文件包含目录、组织依据和章节分工，已有等价文件优先复用 |
| 章节定位与章节框架 | `03-教材框架/章节框架/<chapter_id>.md` | 每章一份，合并保存定位与节级框架；已有明确的章节文件则原位修订 |

以上未存在的路径只是实际框架任务的输出约定，不在建规则时创建空文件。
chapter_id 在框架形成时登记并保持稳定；章序变化更新显示编号，不让知识映射因改名失效。
目录使用教学标题，依据说明保留知识与文献定位；内部 ID 不作为正文标题。
使用 Markdown，自主选择便于审阅的段落、表格与交叉引用；不编写自动生成程序。

## 全书定位应回答的问题

- 面向谁、承担什么教学用途、预设哪些知识基础？
- 研究对象和基本概念如何界定，何种材料在范围之内或之外？
- 历史起讫、空间视野和跨地区比较尺度为什么成立？
- 全书要解释什么历史问题，采取何种史学立场与证据方法？
- 读者读后应获得哪些具体历史认识与分析能力？
- 哪些是现行已确认边界，哪些是本次有依据提出的修订或待定事项？

现行定位中的教材属性、研究对象和中国视角不得因某一目录方案不方便而被静默替换。
全书问题可以统领多条关系与矛盾，不能把复杂历史强行归结为单一必然发展。

## 全书目录框架应包含的判断

- 清楚的目录层级与覆盖范围，以及全书问题如何贯穿其中。
- 分期、章界和章序的历史依据，包含连续、断裂、并存与地区不同步。
- 各章的主要解释任务、独立贡献与必要的知识前提。
- 跨章人物、对象、概念、制度、技术和地区关系的分工与递进。
- 重要选择、舍弃和取舍理由，以及可能挑战框架的材料和替代解释。
- 与所用参考文献和知识单元对应的依据，不以列出几本书名代替实质支持。

全书目录可以使用时代、事件、对象或问题作为标题，但其组织逻辑必须可解释，不能仅因分类方便而成立。

## 每章定位与框架

| 内容 | 要求 |
| --- | --- |
| 章节身份 | chapter_id、当前章序、章名与成果状态 |
| 章节定位 | 全书位置、独立任务、历史与空间范围、取舍边界 |
| 章级问题与判断 | 核心问题、可支持的回答、争议及限制 |
| 教学目标 | 读者需要形成的具体认识、比较或材料辨析能力 |
| 节级框架 | 各节标题、任务、材料责任与相互关系；细化层级由任务决定 |
| 核心材料 | 对象、行动者、制度、概念、事件与案例，说明为何需要它们 |
| 知识与证据 | 对应 unit_id 或实际文献路径与定位，注明核验状态 |
| 章节接口 | 所需前提、与邻章的分工以及适用的承接或转折 |
| 反例与缺口 | 反证、替代解释、未解决来源问题及其对结构的影响 |

这些内容可以用连贯文字表达，不机械填表；不适用的项目说明实际情况，不虚构内容凑齐。
“主语—谓语—宾语”知识单元用于核对历史关系与论证依据，不要求章节标题或框架说明全部写成三元组。
knowledge 的候选、推论或争议状态进入框架时仍须可见；不能因被选入目录就变成已证事实。

## 一致性与成果状态

全书框架是章序、章名和章节分工的现行依据；各章文件细化其任务。修改一方时核对并更新实际受影响的另一方，不复制无关内容。
涉及章界变化时检查前后章和跨章线索；纯措辞修改不要求重新审查全库。
状态区分草案、已核范围内可用、待补证和用户已确认；只有用户确实确认时才能记录最后一种状态。
有足够依据且未越出授权的草案可作为后续工作的可修订输入，不要求每章逐次等待用户确认。
交付时说明已完成层级、实际阅读依据、关键结构取舍和未决限制，不能把“规范建好”表述为“全书框架完成”。
