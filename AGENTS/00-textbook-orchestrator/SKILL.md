# 《现当代设计史》全流程总控

## 目标

把教材开发组织为可核验、可回退的研究流程。每次只处理一个明确阶段；后续阶段的便利不能降低前一阶段的证据要求。

## 启动规则

1. 完整读取仓库根目录 `AGENTS.md`。
2. 读取 `00-参考原则/00_教材写作修辞方法与原则.md`、与任务相关的补充体例，以及 `03-教材框架/00_书籍定位.md`。
3. 现场检查当前目录和文件，不以旧会话、README、Git 历史或项目记忆代替现行状态。
4. 判断本次任务处于哪个阶段，只加载该阶段技能及其明确要求的上游成果。

书籍定位是现行研究边界。除非用户明确要求重新审查，不把框架问题倒推为书籍定位问题。

## 阶段路由

| 阶段 | 技能 | 必须回答的问题 |
| --- | --- | --- |
| 01 | `01-read-project-context` | 当前规则、文件和已确认决定是什么？ |
| 02 | `02-audit-source-corpus` | 实际有哪些材料，它们能承担什么研究责任？ |
| 03 | `03-research-design-historiography` | 主要设计史如何组织历史，各自遗漏了什么？ |
| 04 | `04-model-periodization` | 哪些历史变化足以形成分期与章界？ |
| 05 | `05-build-book-framework` | 全书问题、论证主干与章节分工怎样成立？ |
| 06 | `06-plan-chapter-research` | 某章需要研究、补证和反驳什么？ |
| 07 | `07-verify-chapter-evidence` | 关键事实与判断是否回到可追溯证据？ |
| 08 | `08-plan-chapter-argument` | 材料怎样形成章级论证和节间递进？ |
| 09 | `09-draft-chapter` | 如何把已验证论证写成教材正文？ |
| 10 | `10-review-chapter` | 正文在研究、证据、结构和语言上是否成立？ |
| 11 | `11-integrate-manuscript` | 各章能否组成一部前后一致的总体史？ |
| 12 | `12-prepare-publication` | 注释、书目、图像与交付文件是否达到出版条件？ |

## 阶段门槛

- 阶段可以返回上游修正，不能用下游写作掩盖上游缺口。
- 分析报告用于发现线索和定位原文，不自动获得证据身份。
- 框架、章节规划和正文均只保留一个现行版本；不要创建 `V1`、`V2` 等平行文件。
- 未经用户授权，不创建缺失目录、不改写现行文件、不提交远程变更。
- 用户要求直接修改或提交时，先核验精确目标、当前版本和影响范围；操作完成后再次读取结果。

## 每次交接

阶段输出必须说明：完成了什么、依据是什么、哪些判断已确认、哪些仍为假设、存在哪些证据缺口、下一阶段是否具备启动条件。数量和进度必须带核验日期。

只有输出通过本阶段验收，才把任务移交下一技能。若关键材料不足、关系只能推测或用户尚未确认重大结构决定，应停在当前阶段。
