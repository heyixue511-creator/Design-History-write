# 设计史小节写作工作流

仓库：`heyixue511-creator/Design-History-write`，直接推送 `master`。本 skill 自成一套流程，执行时不以仓库 `AGENTS/` 下的阶段规则为依据，也不修改那些文件。

## 开始前

1. 读取 `04-教材框架/00_书籍定位.md`、`04-教材框架/全书目录.md` 中本节及相邻节、`04-教材框架/章节框架/第N章/` 现有文件、`00-参考原则/《现当代设计史》写作参考原则.md`。先核实路径真实存在，不凭记忆假定。
2. 查 `03-外部来源/`、`05-撰写初稿/`、`05-撰写初稿/证据链/` 中本节文件和提交记录，判断当前阶段，从该阶段继续，不从头重做。
3. 向用户报告：当前阶段、当前最高版本及其提交、本轮将产出的文件名。

## 阶段与确认点

节内单元编号为 `X.Y-①`、`X.Y-②`，不叫“单元二”，避免与小节编号混淆。每阶段完成后停下汇报，等用户确认再进入下一阶段，除非用户已授权连续执行。

| 阶段 | 做什么 | 产出 | 需用户确认 |
|---|---|---|---|
| 1 定位 | 中心问题、中心判断草案、时空范围、与相邻节边界表 | 回复中 | 是 |
| 2 拆单元 | 4—7个节内单元，各写一句本单元任务 | 回复中 | 是 |
| 3 定向检索 | 逐单元联网检索；记录搜索发现、对写作影响、来源可靠性；主动找推翻原设想的材料；对照书籍定位查资本、殖民、劳动等缺口 | `03-外部来源/X.Y.md` | 原设想被推翻时确认修改方向 |
| 4 段落提纲 | 逐段写判断、事实与案例、来源、陈述性质、待核、衔接 | `04-教材框架/章节框架/第N章/X.Y-小节框架提纲.md` | 是 |
| 5 缺口分类 | 分事实细节／原文核对／论证缺口；论证缺口起稿前查清 | 更新提纲 | 判断被推翻时确认 |
| 6 初稿 | 按提纲写连续正文，保留来源标记 | `v1-带来源标记初稿` | 否 |
| 7 证据链 | 参考文献清单选书→`02-文献解析/`报告→只对进入正文的关键点回查`01-基础文献/`原书 | `05-撰写初稿/证据链/X.Y-证据链.md` | 是 |
| 8 实质修订 | 依证据链逐段保留、收缩、改写、删除 | 新版本，如 `v2-修订稿` | 否 |
| 9 结构与语言 | 读写作参考原则后审查；逐处给出“原文→修改后” | 新版本，如 `v3-结构语言修订` | 是，逐处确认 |
| 10 案例审查 | 按三种案例展开形式检查写法、对称性和脚注 | 新版本，如 `v4-案例修订` | 是 |

进入每个阶段时，读取 `references/templates.md` 中对应部分的模板和清单（阶段6、8、9、10共用“版本文件开头”模板）。

## 陈述与证据规则

- 每句陈述分四类：事实／行动者主张／学者解释／作者综合判断。争议概念（如“消费革命”）写成学者解释并列出分歧。
- 措辞强度与证据相称：“部分”“推动”“可能”不得润色为“决定”“导致”“开创”。
- 【作者综合判断】不找相同原话，只查前提是否有据、推论是否越界。
- 联网检索的综合回答只是线索，须打开原始来源核读并保存原始链接；百科、博客、学生论文只作线索。
- 解析报告只作导航，不能替代原书。页码、引文、数字只用证据链已核定的；“禁止写入”清单中的内容不得出现在任何版本。
- 晚于本节时段的材料只能说明“延续多久”，不能描述更早情况。

## 回查停止规则

证据链完成后冻结，不按书目连续回查。只在以下情况定向回查：正文出现具体数字；需要直接引语；核心判断只有解析报告支持；来源之间冲突；用户或审读者要求补证。回查结果并入现有证据链，更新文件开头的版本号，不另建“第二轮”“补遗”文件。

## 版本纪律

1. 正文放在 `05-撰写初稿/`，每次修订新建文件：`X.Y 标题（v{n}-本版说明）.md`。旧版本保持不动，不原位覆盖。
2. 一轮经用户确认的修改合并为一个新版本，不按单处修改拆成多个版本。
3. 新版本必须以当前最高版本的全文为底稿。读取失败就停止并报告，不得凭对话记忆重建正文。
4. 新版本开头写明：版本号、底稿版本及提交标识、本版修改要点、所依据的证据链版本。
5. 写入后给出提交链接。不自行标“定稿”，定稿由用户通读后确认。撤回用还原提交完成，并核对撤回范围。
6. 本节已有无版本号的旧文件时，按提交时间说明其对应版本，不自行改名或删除；新版本号接续最高者。
7. 用户说“先不写入”“在对话中出示”时，只在回复中给出内容，不提交。

## 完成标准

一节完成时应具备：外部来源记录、段落提纲、v1带来源标记初稿、单一证据链、最新版本正文。最新版本中关键事实都能在证据链找到定位，没有“禁止写入”内容，每个案例都能回答“它说明了什么历史机制”，结尾引出下一节的问题。
