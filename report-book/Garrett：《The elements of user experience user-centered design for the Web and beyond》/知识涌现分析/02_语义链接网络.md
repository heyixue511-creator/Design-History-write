# L1 02_语义链接网络：全书知识元的多层关系网络

## L2 一、网络构建总述

### L3 1.1 网络构建参数

| L4 参数 | L4 取值 |
|---------|--------|
| 节点总数 | V = 233（全部实体） |
| 节点类型 | 六类：KE-P(23), KE-C(45), KE-M(33), KE-O(22), KE-D(24), KE-T(86) |
| 关系类型 | 十类：R1_定义-被定义, R2_因果依赖, R3_类比映射, R4_对立张力, R5_工具应用, R6_实例化, R7_共现协同, R8_演化-替代, R9_桥接中介, R10_层间穿透 |

### L3 1.2 网络的双层结构

本书的知识网络本质上是一个**双层网络**：

- **概念层（上层）**：KE-C, KE-T, KE-M（概念实体、术语实体、方法实体）——这是网络的"骨架"，承载了全书的论证逻辑。
- **实例层（下层）**：KE-P, KE-O, KE-D（人物实体、机构/产品实体、文献/图表实体）——这是网络的"实例锚点"，为上层概念提供经验支撑。

两层之间的链接（R6_实例化, R5_工具应用）是将抽象概念"接地"的关键机制。当我们在后续章节进行社区发现和桥接检测时，双层结构将是关键的分析维度。

## L2 二、十类语义关系的详析

### L3 2.1 R1_定义-被定义关系（→def）

这是全书最基础的关系类型，定义了"概念包含关系"的树状层级。

**核心定义链**：

```
User Experience（用户体验）
    →def The Five Planes（五平面模型——UX可被分解为五个平面）
        →def Strategy Plane（战略层）
            →def Product Objectives（产品目标——内部）
            →def User Needs（用户需求——外部）
            →def Success Metrics（成功指标——量化）
            →def Brand Identity（品牌认同）
        →def Scope Plane（范围层）
            →def Functional Specifications（功能规格）
            →def Content Requirements（内容需求）
            →def Scope Creep（范围蔓延——反面定义）
        →def Structure Plane（结构层）
            →def Interaction Design（交互设计）
                →def Conceptual Model（概念模型）
                →def Error Handling（错误处理）
            →def Information Architecture（信息架构）
                →def Nodes（节点）
                →def Organizing Principles（组织原则）
                →def Facets（分面）
                →def Controlled Vocabulary（受控词表）
                →def Metadata（元数据）
                    →def Thesaurus（叙词表——升级版受控词表）
        →def Skeleton Plane（骨架层）
            →def Interface Design（界面设计）
            →def Navigation Design（导航设计）
                →def Wayfinding（寻路）
                →def Global/Local/Supplementary/Contextual/Courtesy Navigation
            →def Information Design（信息设计）
        →def Surface Plane（表现层）
            →def Sensory Design（感官设计）
                →def Contrast and Uniformity（对比与统一）
                →def Visual Hierarchy（视觉层级）
                →def Grid-based Layout（网格布局）
```

**统计特征**：定义链的最大深度为6层（User Experience → Five Planes → Structure Plane → Information Architecture → Metadata → Thesaurus），平均深度约3.5层。这一深度体现了Garrett概念的"适度层级化"——足够深以展示系统性，但不过深以致于引发概念过载。

### L3 2.2 R2_因果依赖关系（→cau）

这是全书最具理论强度的关系类型，体现了Garrett的"层级依赖"核心主张。

**核心因果链**：

```
Strategy Plane（战略层）
    →cau Scope Plane（范围层——范围由战略决定）
        →cau Structure Plane（结构层——结构由范围决定）
            →cau Skeleton Plane（骨架层——骨架由结构决定）
                →cau Surface Plane（表现层——表现由骨架决定）
```

**双向因果（涟漪效应）**：

```
Surface Plane（表现层）
    →cau [反推] Skeleton Plane（表现层的发现可迫使骨架层重新思考）
        →cau [反推] Structure Plane（沿链上溯）
```

**跨链因果**：

```
Product Objectives（产品目标）
    →cau Functional Specifications（功能规格——产品目标决定需要什么功能）
    →cau Success Metrics（成功指标——产品目标定义了如何度量成功）

User Needs（用户需求）
    →cau Content Requirements（内容需求——用户需求决定需要什么内容）
    →cau Personas（Personas是用户需求的表达工具）

Scope Creep（范围蔓延）
    →cau [负面] Project Derailment（项目脱轨——未管理范围导致失败）

Design by Default / by Mimicry / by Fiat
    →cau [负面] Bad User Experience（不良用户体验——跳过底层直接做上层）
```

**统计特征**：因果依赖关系在五平面之间的密度最高（层间因果边占总因果边的约60%），其次是平面内部的概念→方法因果边（约30%），跨域的因果边最少（约10%）。这种分布印证了Garrett以"层间依赖"为核心组织逻辑的结构特征。

### L3 2.3 R3_类比映射关系（→ana）

这是全书密度最高的"认知脚手架"关系类型，Garrett通过日常生活类比将抽象UX概念锚定在读者日常经验中。

**全书类比映射总表**：

| L4 源域（Source） | L4 目标域（Target·UX概念） | L4 映射机制 |
|-------------------|--------------------------|------------|
| 建筑地基与屋顶 | 战略层与表现层的依赖关系 | 底层决定上层——不能先盖屋顶再打地基 |
| 人体骨骼 | 骨架层（Skeleton Plane） | 结构支撑+不可见但决定形态 |
| 建筑蓝图 | 线框图（Wireframe） | 施工前必画图——线框图是页面的"蓝图" |
| 建筑立面 | 表现层（Surface Plane） | 用户看到的"外立面" |
| 双人舞 | 用户与系统的交互 | 相互适应、不能单方面主导 |
| 马拉松vs.短跑 | 产品开发节奏 | 长跑需节奏控制，短跑需爆发——不同场景不同策略 |
| 传话游戏（Telephone Game） | 口头传递需求导致的信息失真 | 口口相传→逐级失真→文档化的必要性 |
| 水面涟漪 | 决策在五平面间的传播 | 投石入水→波纹向外扩散——涟漪效应 |
| 滚雪球 | 范围蔓延（Scope Creep） | 小雪球越滚越大越难停——范围越加越多越失控 |
| 火车脱轨 | 项目失控 | 偏离轨道→灾难性后果 |
| 超市购物车 | 电商的选购组件 | 容器隐喻——"把商品放进购物车" |
| 物理空间寻路 | 信息空间导航 | 在陌生建筑中找路的经验→在陌生网站中找路的经验 |
| 光学镜片 | 导航设计 | "导航是用户看穿信息架构的镜片" |
| 灰色无特征的大块 | 缺乏对比度的视觉设计 | 阴天/雾气的视觉经验→视觉混乱的体验 |
| 火箭/爆炸 | 成本飙升 | 失控的急剧上升 |

**统计特征**：在15个主要类比映射中，建筑/构造隐喻群占据5个（33%），运动/身体隐喻群占据3个（20%），自然/灾害隐喻群占据3个（20%），容器/空间隐喻群占据3个（20%），其他1个（7%）。建筑隐喻的主导地位不是偶然——它服务于Garrett的核心论证框架（"用户体验像盖房子"），赋予全书以意象统一性。

### L3 2.4 R4_对立张力关系（→opp）

这是全书中最具"哲学深度"的关系类型——通过概念对立制造认知张力，推动论证前进。

**核心对立张力对**：

| L4 正概念 | L4 反对概念 | L4 张力的论证功能 |
|-----------|------------|-----------------|
| "Conscious, Explicit Decision"（有意识的、明确的决策） | Design by Default（跟随技术/组织结构） | 主动设计 vs. 被动接受 |
| "Conscious, Explicit Decision" | Design by Mimicry（盲目复制） | 基于情境的判断 vs. 基于惯例的盲从 |
| "Conscious, Explicit Decision" | Design by Fiat（个人偏好驱动） | 基于证据的协商 vs. 基于权力的独断 |
| User-Centered Design（以用户为中心） | Design by Default / Mimicry / Fiat | 用户需求驱动 vs. 技术/惯例/权力驱动 |
| Asking the Right Questions（提出正确问题） | 直接跳到解决方案 | 认识论优先 vs. 方法论优先 |
| Marathon Strategy（马拉松策略——节奏控制） | Sprint Strategy（短跑策略——全速冲刺） | 可持续的构建 vs. 一次性的爆发 |
| User Needs（用户需求——外部） | Product Objectives（产品目标——内部） | 辩证张力——好的战略是两者的合成 |
| Functionality Side（功能侧） | Information Side（信息侧） | 互补性张力——好的设计是两者的整合 |
| Internal Consistency（内部一致性） | External Consistency（外部一致性） | 设计系统的两条腿——缺一不可 |
| Contrast（对比——制造差异） | Uniformity（统一——制造秩序） | 表现层的核心辩证法——对比与统一的精妙平衡 |
| Top-down IA（自上而下——从分类到内容） | Bottom-up IA（自下而上——从内容到分类） | 信息架构的两种构建路径——各有优劣 |
| "finish before next can start"（完成后下一层再开始） | "finish before next can finish"（开始后交错完成） | 线性的僵化 vs. 迭代的灵活 |
| User Testing as Substitute（测试作为设计的替代品） | User Testing as Complement（测试作为设计的辅助品） | 偷懒的迭代 vs. 知情的迭代 |
| Shared Vision（共享愿景——小团队的优势） | Communication Overhead（沟通开销——大团队的劣势） | 团队规模的反直觉辩证 |

**统计特征**：对立张力关系呈现一个清晰的"中心辐射"模式——"Conscious, Explicit Decision"是张力网络的绝对中心，与三种反模式（Default/Mimicry/Fiat）和"直接跳到解决方案"形成对立。这一模式印证了01_知识元语意分析中的发现：全书的知识体系以"刻意决策"为最高规范性原则，所有反面概念都是对这一原则的违反而被定义的。

### L3 2.5 R5_工具应用关系（→app）

连接方法/工具实体与其应用的概念/问题。

**工具-概念应用映射**：

```
Personas（用户角色模型）
    →app User Needs（用户需求——Personas用于表达用户需求）
    →app User Segmentation（用户细分——Personas锚定细分）

Card Sorting（卡片分类法）
    →app Information Architecture（信息架构——卡片分类用于探究用户心智分类）
    →app User Needs（用户需求——探究用户如何理解信息）

Wireframes（线框图）
    →app Interface Design（界面设计——线框图确定界面元素的位置）
    →app Navigation Design（导航设计——线框图包含导航元素）
    →app Information Design（信息设计——线框图安排信息的布局）

Style Guide（风格指南）
    →app Internal Consistency（内部一致性——风格指南确保设计一致性）
    →app External Consistency（外部一致性——风格指南也维护跨产品一致性）
    →app Organizational Amnesia（组织性失忆——风格指南对抗人员流失导致的知识流失）

Content Inventory（内容清单）
    →app Content Requirements（内容需求——盘点现有内容以确定需求）
    →app Information Architecture（信息架构——为信息架构提供内容基础）

Visual Vocabulary（视觉词汇表）
    →app Information Architecture（信息架构——用标准化符号绘制架构图）
    →app Architecture Diagram（架构图——视觉词汇表的输出产品）
```

**统计特征**：方法/工具实体（33个）与概念/术语实体的应用链接呈现出一种"一对多"的辐射模式——一个方法通常服务于多个概念目标。例如Wireframes同时服务于界面设计、导航设计和信息设计；Style Guide同时服务于内部一致性、外部一致性和组织性失忆防御。这种"一对多"的工具-概念映射表明，Garrett并未发明"针对性"的新工具（每个概念一个专属工具），而是展示了已有工具如何在五平面模型中服务于多个目标——这再次印证了本书的定位："为已有工具提供位置框架"。

### L3 2.6 R6_实例化关系（→ins）

连接抽象概念与具体实例。

**典型实例化链**：

```
Design by Mimicry（设计by mimicry）
    →ins Southwest Airlines旧网站（过度隐喻——将Web导航做成飞机舱内隐喻）
    →ins Slate（杂志隐喻——将新闻评论网站做成印刷杂志隐喻）

Design by Default（设计by default）
    →ins 数据库驱动UX（客户的订单历史与账单信息分属不同数据库→UX中也分开呈现）

Successful Brand Identity through Sensory Design
    →ins TiVo（声音设计——"哔哔"声的品牌化）
    →ins Apple（定制字体——品牌识别）
    →ins Coca-Cola / UPS / Kodak（色彩与品牌——红/棕/黄）
    →ins London Underground（字体与品牌——定制字体）
    →ins Volkswagen（定制字体——品牌识别）

Successful Color Palette
    →ins Orbitz（有限色彩调色板——商业应用）

Featuritis →ins Microsoft Word的过度自动纠错
Self-blame →ins [第一章·倒霉的一天] 闹钟→咖啡机→加油站→收银机 的用户自责
```

**统计特征**：正面实例化链的数量（约12条）远超负面实例化链（约5条），比例为2.4:1。但在论证强度上，负面实例化链的描述远比正面实例化链更生动、更具体——Southwest Airlines的失败案例用了大幅截图，Microsoft Word的过度纠错配以讽刺性评论，而TiVo的成功案例只是一句带过。这种"负案例更生动"的不对称性反映了Garrett的修辞策略：以生动反例唤起"这是坏设计"的直觉，再以正面案例示范"好的应该怎样做"。

### L3 2.10 R10_层间穿透关系（→cro）

识别影响跨越多个平面的概念。

**主要层间穿透概念**：

| L4 穿透概念 | L4 穿透的平面 | L4 穿透方式 |
|------------|-------------|------------|
| Brand Identity（品牌认同） | 战略层 → 范围层 → 结构层 → 骨架层 → 表现层 | 战略定义→内容规划→信息组织→导航呈现→视觉表达 |
| Ripple Effect（涟漪效应） | 所有五个平面（双向） | 任一平面的决策通过涟漪效应影响其他平面 |
| Success Metrics（成功指标） | 战略层 → 表现层 | 战略定义可度量指标→表现层是用户直接感知的层级→指标可通过表现层设计来改善 |
| "Conscious, Explicit Decision" | 所有五个平面 | 这一方法论原则要求每个平面的每一项决策都应该是刻意的 |

## L2 三、子网络分析

### L3 3.1 五平面子网络

对网络按D3_平面归属切分，得到六个子网络（五个平面 + 全局层），各自的特征如下：

| L4 子网络 | L4 节点数 | L4 边密度 | L4 核心枢纽节点 | L4 子网络特性 |
|-----------|----------|----------|---------------|-------------|
| 战略层子网络 | 约25节点 | 中等 | Product Objectives, User Needs, Success Metrics | 以"内部/外部"双向张力为核心结构 |
| 范围层子网络 | 约16节点 | 偏低 | Scope Creep, Functional Specifications, Content Requirements | 最稀疏的子网络——节点少且连接少 |
| 结构层子网络 | 约36节点 | 高 | Interaction Design, Information Architecture, Conceptual Model | 最密集的子网络——概念间相互关联最紧密 |
| 骨架层子网络 | 约30节点 | 中高 | Wireframes, Navigation Design, Interface Design | 以Wireframes为终极整合点 |
| 表现层子网络 | 约29节点 | 中等 | Contrast and Uniformity, Visual Hierarchy, Style Guide | 以"有效传达"而非"美学"为核心价值 |
| 全局层子网络 | 约32节点 | 中高 | User Experience, Five Planes, Ripple Effect, Basic Duality | 元概念枢纽群——支配所有平面子网络 |

**关键发现**：
1. **结构层是网络密度之王**——36个节点形成了全书最密集的连接网络。这与01_知识元语意分析中"概念实体集中分布在第2-3层（结构层附近）"的发现高度一致。结构层在Garrett知识体系中的"概念引力"远超其他平面。
2. **范围层是网络密度之谷**——仅16个节点，且节点间的连接稀疏。这证实了01_知识元语意分析中的初步判断：范围层是全书知识体系的"最薄弱层"。
3. **全局层子网络的"支配者"角色**——全局概念（User Experience, Five Planes, Ripple Effect等）与所有五个平面子网络都有跨层连接，其在网络结构上扮演着"中枢控制"的角色。

### L3 3.2 功能/信息双轨子网络

按D4_二元极性将节点分为功能侧（F）、信息侧（I）、双侧融合（F+I）和元层面（Meta），分析跨极性边界的关系密度：

| L4 链接方向 | L4 边密度 | L4 说明 |
|------------|----------|--------|
| F → F（功能侧内部） | 高 | 功能概念形成了紧密的内部网络 |
| I → I（信息侧内部） | 高 | 信息概念也形成了紧密的内部网络 |
| F → I（跨极性） | 中等 | 功能侧与信息侧之间存在跨极性链接 |
| Meta → F | 高 | 元层面概念大量连接到功能侧 |
| Meta → I | 高 | 元层面概念同样大量连接到信息侧 |
| Meta → F+I | 最高 | 元层面概念与双侧融合概念的连接密度最高 |

**关键发现**：元层面概念（Meta）是功能侧和信息侧之间的"翻译层"——它不与任何一方的内部网络脱离，而是同时密集连接到两侧。这一结构特征印证了Garrett"给两方各自合法的位置"的论证意图——元层面概念在网络上确实充当了功能社区和信息社区之间的桥接设施。

### L3 3.3 隐喻子网络

全书15个主要隐喻构成了一个以"建筑隐喻"为核心的隐喻子网络：

```
[建筑隐喻核心群]
    地基与屋顶 →ana→ 战略层↔表现层依赖关系
    骨架 →ana→ 骨架层（页面布局）
    结构 →ana→ 结构层（信息组织）
    蓝图 →ana→ 线框图
    立面 →ana→ 表现层

[运动/身体隐喻群] ←→ 建筑隐喻群（共享"层次/顺序"意象）
    舞蹈 →ana→ 用户-系统交互
    马拉松/短跑 →ana→ 开发节奏
    传话游戏 →ana→ 需求失真

[自然/灾害隐喻群] ←→ 建筑隐喻群（负面镜像——建筑隐喻构建，自然隐喻破坏）
    涟漪 →ana→ 跨层决策传播
    雪球 →ana→ 范围蔓延
    脱轨 →ana→ 项目失控
    暴涨 →ana→ 成本飙升

[容器/空间隐喻群] ←→ 运动隐喻群（共享"空间/移动"意象）
    购物车 →ana→ 电商选购组件
    寻路 →ana→ 信息空间导航
    镜片 →ana→ 导航设计
```

**隐喻网络的结构特征**：
1. **以建筑为核心、其他为卫星**：建筑隐喻群是整个隐喻网络的中心——其他隐喻群的意象（运动、自然、容器）都与建筑隐喻共享某种底层意象（结构、顺序、层次）。
2. **正面/负面的意象分工**：建筑+运动隐喻主要承载正面意象（构建、节奏、协作），自然/灾害隐喻主要承载负面意象（失控、破坏、灾难）。这种分工使隐喻体系具有了"道德评述"的功能——不是中立的类比，而是带有价值判断的"好/坏"标签。
3. **隐喻的内聚力来源**：隐喻网络的内聚力并非来自隐喻之间的显式链接，而是来自它们共同锚定的目标域——五平面模型。所有隐喻都从不同角度照射同一个核心框架。

## L2 四、关键节点的多边聚合分析

### L3 4.1 "五平面模型"节点的聚合关系

作为全书最核心的概念节点，"The Five Planes"聚合了七类不同性质的关系：

| L4 关系类型 | L4 链接对象 | L4 关系内容 |
|------------|------------|------------|
| R1_定义 | 五个平面各自 | 五平面模型包含并定义五个平面 |
| R2_因果 | Strategy → Scope → Structure → Skeleton → Surface | 定义了五平面间的依赖链 |
| R3_类比 | 建筑地基-屋顶隐喻 | "五平面模型像建筑层次" |
| R4_对立 | 无明确对立概念 | 五平面模型作为框架本身，不处于对立关系中 |
| R7_共现 | Basic Duality, Ripple Effect | 五平面模型与二元性、涟漪效应共构核心框架 |
| R9_桥接 | 全书几乎所有概念 | 五平面模型是最大范围的桥接概念——它将UX的所有子学科连接到各自的位置 |
| R10_层间穿透 | 所有层间穿透概念 | 五平面模型是所有层间穿透发生的基础框架 |

**节点特性**："五平面模型"节点的介数中心性（betweenness centrality）预计为全书最高——它在网络上扮演着"总开关"的角色，几乎所有跨子网络的信息流都必须经过它。

### L3 4.2 "Ripple Effect"节点的聚合关系

| L4 关系类型 | L4 链接对象 | L4 关系内容 |
|------------|------------|------------|
| R1_定义 | 五平面模型 | 涟漪效应是五平面模型中决策传播的动态机制 |
| R2_因果 | 各平面→其他平面 | 描述"A平面决策→B平面被影响"的因果关系 |
| R3_类比 | 水面涟漪 | "像石头投入水中产生的波纹" |
| R7_共现 | 五平面模型, Basic Duality | 与模型和二元性共同构成核心框架 |
| R10_层间穿透 | 所有五个平面 | 涟漪效应本身就是关于"层间穿透"的机制描述 |

**节点特性**："Ripple Effect"在概念上是"五平面模型"的动力学补充——如果"五平面模型"定义了静态结构（五个层次是什么），"涟漪效应"则定义了动态机制（决策如何在层次间移动）。两者在网络中预计呈现"紧密耦合"模式——高权重边、高共现度。

### L3 4.3 "Conscious, Explicit Decision"节点的聚合关系

| L4 关系类型 | L4 链接对象 | L4 关系内容 |
|------------|------------|------------|
| R4_对立 | Design by Default | 刻意决策 vs. 被动跟随技术结构 |
| R4_对立 | Design by Mimicry | 刻意决策 vs. 盲目复制惯例 |
| R4_对立 | Design by Fiat | 基于证据的协商 vs. 基于权力的独断 |
| R7_共现 | User-Centered Design | 刻意决策是以用户为中心设计的方法论前提 |
| R7_共现 | "Asking the Right Questions" | 提出正确问题是做出刻意决策的认识论前提 |
| R10_层间穿透 | 所有五个平面 | 每一层的每一项决策都应该是刻意的 |

**节点特性**："Conscious, Explicit Decision"是一个以其对立面来定义自身核心地位的概念——它的网络重要性不是来自"它连接了多少概念"（正连接数量中等），而是来自"它与多少反概念形成了对立张力"（对立张力边数量为全书最高）。这是一个以"否定性"来建立"肯定性"的独特网络结构。

### L3 4.4 "Brand Identity"节点的跨层聚合关系

"Brand Identity"是全书网络中最典型的"跨层穿透型"节点：

```
战略层：Brand Identity作为战略级产品目标 →def 用户应形成的概念联想与情感反应
    →cau
范围层：Brand Identity影响内容选择与功能优先级 →app Content Requirements
    →cau
结构层：Brand Identity影响信息组织方式 →app Information Architecture
    →cau
骨架层：Brand Identity影响导航与界面设计 →app Navigation Design
    →cau
表现层：Brand Identity通过色彩/字体/图像传达 →app Sensory Design
    →ins
    Coca-Cola(红), UPS(棕), Kodak(黄), Apple(定制字体), Volkswagen(定制字体)
```

"Brand Identity"是少数几个被Garrett在多个章节中反复提及的跨层概念之一，其网络结构完整地展示了"如何从一个战略概念转化为全栈设计表达"的五层穿透路径。

## L2 五、网络整体拓扑特征

### L3 5.1 稀疏性与枢纽性并存

全书知识网络呈现"整体稀疏、局部密集"的拓扑特征——大多数实体对之间不存在直接的语义链接（整体稀疏），但少数核心概念（Five Planes, User Experience, Ripple Effect, 五个平面各体）与其他节点形成了大量的连接（枢纽密集）。这一"无标度"拓扑结构对于知识涌现的意义将在03_知识涌现计算中展开分析。

### L3 5.2 "核心-边缘"结构

网络呈现明显的核心-边缘（core-periphery）结构：
- **核心区**（约15个节点）：Five Planes, 五个平面各体(5), User Experience, UCD, Ripple Effect, Basic Duality, "Conscious, Explicit Decision", Brand Identity, Conversion Rate, Marathon vs. Sprint
- **过渡区**（约40个节点）：各平面的核心子概念（Interaction Design, Information Architecture, Wireframes等）、关键方法/工具（Personas, User Testing等）、核心术语
- **边缘区**（约178个节点）：具体案例机构、人物（除Garrett本人）、具体图表、非核心术语

这种"核心-边缘"结构与01_知识元语意分析中的"金字塔式知识结构"互为表里：核心区对应第1-2抽象层（元认知+框架），过渡区对应第3层（方法+内部构件），边缘区对应第4-5层（操作文档+实例案例）。

### L3 5.3 模块性初步评估

基于网络在平面归属和学科来源上的不均匀连接分布，预期网络具有中等偏高的模块性（Modularity Q ≈ 0.4-0.6）。各平面子网络内部的连接密度显著高于跨平面连接密度，形成了一个"层内紧密、层间稀疏"的模块化结构。具体的社区划分将在03_知识涌现计算中通过Louvain算法精确计算。
