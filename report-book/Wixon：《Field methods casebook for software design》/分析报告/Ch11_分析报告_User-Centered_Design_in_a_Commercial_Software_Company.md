# Ch11 分析报告：《User-Centered Design in a Commercial Software Company》

## 一、章节定位与功能（行号范围 L3240-L3464）

本章是第五主题簇"EXAMPLES OF CONTEXTUAL INQUIRY AND CONTEXTUAL DESIGN"（L542-L544）首篇，作者 Stanley R. Page（Corel Corporation；研究在 WordPerfect/Novell 完成，L3242-L3244）。功能：展示大软件公司如何以**情境设计（Contextual Design）**流程做客户研究，作为新一代 WordPerfect 字处理应用的输入；以及成功后如何扩展为多研究团队协调体系（L3248）。

## 三、内容分析

**背景**：WordPerfect 诞生于 Orem 市办公楼下——Alan Ashton 与 Bruce Bastian 为市政府的 Data General 电脑写字处理程序，在楼下写代码、上楼让打字员试用的"场中设计"（L3252-L3254）。公司成长后，客户支持电话、可用性测试、正式实验、非正式焦点组成为反馈渠道，但这些来得太晚或脱离真实工作（L3256-L3260）。

**规划**：由开发执行副总裁建立小团队，范围"刻意保持很宽"——研究制作文档的工作实践（构思、创建、评审/批准、分发）（L3266-L3268）；跨学科团队（WP 开发、人因、文档、市场、可用性测试）全职投入（L3272）。

**过程**：采用 Holtzblatt & Beyer（InContext Enterprises）教的情境设计流程（L3278）。六个月内三周培训，每周培训后四周实践（L3280）。参与者覆盖各行业/地区/大小公司、使用我方与竞品软件及不用电脑者（L3284）；来源：市场研究数据、注册用户名单、区域销售、团队成员熟人（L3288-L3294）；数据解释逐轮细化参与者选择（L3296）。

**问题**：现场被安排成焦点组（L3302）；被当"解决问题的人"（L3304）；难接触高层管理者（L3306）。

**访谈**：2-3 小时，在用户工作场所进行；把被访者当伙伴、可随时终止、保密；聚焦典型任务并细笔记；录磁带（24-48 小时内解释则不必回听）（L3310-L3314）。

**数据分析**：整个团队做初始解释，一人录"电子卡片"，他人画模型（L3318）：工作流模型（角色=圆、制品=矩形，L3320）、序列模型（含触发器与意图，L3325）、物理模型（L3327）；**情境模型**被认为无益而弃用（L3329）。数据组织：亲和图（电子卡片打印后按相似性排序，自然类别浮现成大纲，L3338）；合并模型（合并流/物理/序列，L3340）；再设计工作模型（消除步骤避免 breakdown，L3345）；用户环境模型（从用户视角的蓝图，独立于 UI/平台，L3347）；界面设计（先纸原型后 ToolBook/Delphi 运行原型，L3352）。

**扩展**：研究见效后团队一分为二：一个字处理团队、一个"总体团队"（含电子表格、电子表单、图形/演示、通信、文档管理专家）研究整个商业工作实践（L3356-L3366）。一名成员同时属于公司软件过程委员会，使情境设计成为公司产品生命周期批准流程（L3368）。子团队研究字处理、图形、图表、表单、幻灯片等领域（L3372-L3374）。

**团队间沟通**：联络员（效果平平，L3384）；导师（更有效，L3386）；模型电子共享（L3388）；开放日（L3390）；公告板（L3392）；设计评审（L3394）。

**落地特性**：
- **Make It Fit**：把文本缩放到特定空间的需求 → WordPerfect 6.1 for Windows 实现，获好评（Lombardi 1994）（L3406）；
- **QuickTasks**：跨应用任务自动化，推动用户从"应用中心"转向"任务导向"（PerfectOffice 3.0），获好评（Bethoney 1995）（L3410）。

**教训**：跨学科团队提升效果（L3419）；输出不必完美，快速迭代（L3421）；每日流程检查（L3423）；别纠结于流程本身（L3425）；经常回到用户（L3427）；留时间汇报与推销想法（L3429）；用运行原型打动管理层（L3431）；"用流程帮助推销想法"——数据支撑的想法少有争议（L3433）。

**结论**：情境设计给了团队"逻辑性、系统性的研究用户方法"（L3437）；多团队同流程提供共同词汇与共同愿景（L3439）；用户环境模型成为长期蓝图（L3441）；研究获持续资助并轮换新人（L3443）。

## 四、逻辑梳理

**WordPerfect 起源的"场中设计" → 成长后的反馈渠道退化 → 情境设计全流程（培训+数据+模型）→ 数据组织（亲和图/合并模型/UE）→ 扩展为多团队（总体+子团队）→ 沟通机制 → 落地特性（Make It Fit/QuickTasks）→ 教训与制度化**。逻辑核心：用结构化流程在规模化公司中"找回初创时的用户亲密度"（L3260）。

## 五、材料使用方式

- **一手材料**：访谈笔记/录音、电子事实卡、各模型图（图 11.1-11.6）、亲和图（图 11.5）、原型。
- **产出到产品**：以 Make It Fit、QuickTasks 两个真实产品特性作为田野研究影响力的实证（L3406-L3410）。
- **参考文献**：情境设计（Holtzblatt & Beyer 1993；Holtzblatt & Jones 1993；Wixon/Holtzblatt/Knox 1990）、可用性工程（Whiteside/Bennett/Holtzblatt 1988）、评审引证（Lombardi 1994；Bethoney 1995）。

## 六、论辩与阐述方法

- **历史-退化-回归叙事**：以"初创期场中设计"为理想原点，论证规模化后需要结构化流程（L3252-L3260）。
- **流程结构论**：以模型类型清单与合并步骤展示流程的可操作性。
- **成效实证**：以产品特性与外部媒体评价收束（L3406-L3410）。
- **自陈取舍**：弃用情境模型（L3329）、联络员效果不佳（L3384）。
