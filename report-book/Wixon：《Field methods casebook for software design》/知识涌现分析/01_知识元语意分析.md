# 知识涌现分析 01：知识元语意分析

## 一、总述：六类实体的五种论证功能

在本书中，六类知识元（人物 P、著作/作品 A、概念 C、机构 I、地点 L、事件 E）承担五种主要论证功能。先总述功能，再按类分述语义载荷。

**功能一：因果节点（Causal Node）** —— 作为方法/结果的因或果，构成因果链端点。
- 例：1969 年"软件危机"（E）→ 层级化软件工程模型（C）→ 被跨职能团队（C）替代（L1363）；田野数据（C）→ 推翻设计假设（C）（L1496）。
- 代表实体：软件危机、田野数据、设计假设。

**功能二：结构变量（Structural Variable）** —— 作为影响方法成败的可变条件，承担"若…则…"逻辑。
- 例：组织支持（C，Ch4 L1657）、跨职能结构（C，Ch7 L2224）、变更控制通道（C，Ch7 L2319）、时间约束（C，Ch10）——均作为条件变量出现。
- 代表实体：跨职能团队、管理支持、时间窗、变更控制系统。

**功能三：类型标签（Type Label）** —— 作为方法/现象的类别命名，供比较与归类。
- 例：Ethnography（C）、Participatory Design（C）、Contextual Design（C）是三大"学派标签"（L576）；三类现场研究（L2596-L2606）；三种快速技术（Ch10）。
- 代表实体：Ethnography、Participatory Design、Contextual Design、CARD、PICTIVE。

**功能四：证据载体（Evidence Carrier）** —— 作为论证的可检验证据来源。
- 例：行为流录像带（A，L692）、访谈转录（A，Ch9 L2694-L2718）、工作模型/亲和图（A，L3338、L4971）、需求文档（A，L3819）、客户原话（P/A 层证据，L1642-L1651）。
- 代表实体：行为流编年、亲和图、工作模型、需求文档、客户原话。

**功能五：参照坐标（Reference Coordinate）** —— 作为历史/空间/机构坐标系，锚定论证的时空位置。
- 例：斯堪的纳维亚（L，L4543-L4553）锚定参与式设计起源；Digital、Microsoft、Lotus 等机构（I）锚定方法的应用场景；CHI '95 工作坊（E，L428）锚定成书背景。
- 代表实体：斯堪的纳维亚、CHI '95、Ericsson、Microsoft、Digital Equipment Corporation。

## 八、五种论证功能小结表

| 功能 | 代表知识元 | 计数（近似） |
|---|---|---|
| 因果节点 | 软件危机、CHI'95、Whiteside 挑战、亲和图、用户环境模型 | ~18 |
| 结构变量 | 跨职能团队、管理支持、时间窗、变更控制、组织支持 | ~8 |
| 类型标签 | 三大方法学派、CARD/PICTIVE/CI/CD/PD/Delta/圆桌 | ~15 |
| 证据载体 | 行为流录像、转录、工作模型、亲和图、需求文档、客户原话 | ~12 |
| 参照坐标 | 斯堪的纳维亚、Digital、Microsoft、Lotus、CHI | ~14 |

这一分布显示：本书作为"方法学案例集"，概念（类型标签+因果节点）与机构/事件（参照坐标+证据载体）构成主体，人物主要承担"方法人格化"的因果节点角色。
