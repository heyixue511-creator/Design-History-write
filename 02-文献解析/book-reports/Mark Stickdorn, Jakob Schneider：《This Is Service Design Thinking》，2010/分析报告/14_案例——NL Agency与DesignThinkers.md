# 14_章节分析报告：案例——NL Agency与DesignThinkers

## L### 一、章节定位与功能

本章是Part 5（"Applied Service Design Cases"）的首个案例，由Arne van Oosterom（DesignThinkers创始人）执笔。在全书的案例序列中，本章的功能是**展示服务设计思维在政府公共服务领域的应用**——具体呈现了DesignThinkers如何为荷兰政府机构NL Agency（一家为市政当局、企业和组织提供多种服务的机构）设计和运营一个"客户旅程实验室"（Customer Journey LAB）。这个案例的核心贡献在于：证明了服务设计的方法不仅适用于商业领域，也同样——甚至更迫切地——适用于公共服务领域。

## L### 二、结构分析

本章的结构叙事遵循了Ch09的四步框架精神，但以案例特有的"故事化"方式展开：

1. **背景介绍**：NL Agency的不同部门向荷兰不同类型的组织提供不同服务。挑战：如何整合这些碎片化的服务？
2. **人物角色"Hans"**：通过创建一个代表性人物角色（Persona）来模拟客户的存在——参与者被"强制"从Hans的视角思考
3. **情感客户旅程**：逐层构建情感客户旅程地图——从"水面之上"（可见的客户行为）开始，慢慢"潜入"水面之下（情感和动机）
4. **共同创造：与客户一起开发解决方案**：真正的共同创造基于与客户一起开发有价值的解决方案——采用优先级排序、投票和共识建立等方法
5. **最终声明**：客户旅程实验室"构建了一面镜子，使我们能够质疑我们为什么做我们所做的事。它使不可见的事物变得可见。"

## L### 三、内容分析

### 3.1 核心论题

**政府公共服务的碎片化是一个普遍难题——不同部门各自为政，而公民的需求是跨部门的。服务设计——特别是客户旅程实验室的方法——提供了一种将"组织视角"（各部门各自提供什么服务）转换为"公民视角"（公民需要什么，无论由哪个部门提供）的系统性手段。**

### 3.2 关键论点

**人物角色"Hans"的价值**：通过在实验室中创建一个具体的人物角色（有姓名、背景故事、需求和痛点的"真人"），参与者得以从"我是X部门的主管"转变为"如果我是Hans，我会怎么想"。角色扮演使得"以用户为中心"从抽象原则变为具体实践。

**情感客户旅程地图的"冰山"方法**：从"水面之上"（可见行为）到"水面之下"（情感和动机）的逐层分析——这与Ch04（Miettinen）的"效用→可用性→愉悦性"三层体验模型形成呼应。

**共同创造的真正含义**："基于与客户一起开发有价值的解决方案"——不是"咨询客户的意见"，而是"将客户纳入创造团队"。

### 3.3 关键案例详情

- **NL Agency的背景**：一个典型的"服务碎片化"的政府机构——不同部门提供不同服务，但顾客（公民）需要的是一个统一、一致的服务体验
- **Customer Journey LAB的运作方式**：一个物理的/虚拟的实验空间，在其中：(1) 展示人物角色和旅程地图；(2) 进行共同创造工作坊；(3) 可视化当前服务的问题和新服务的概念
- **情感客户旅程地图的构建过程**：逐层添加数据——先画行为层，再加情感层，最后连接动机层

## L### 四、逻辑梳理

```
政府公共服务的碎片化问题
    ↓ （视角转换）
从组织视角 → 公民视角
    ↓ （方法）
创建人物角色（Persona "Hans"）
    ↓ （深度分析）
构建情感客户旅程地图（行为→情感→动机）
    ↓ （解决方案生成）
共同创造工作坊（与客户一起开发解决方案）
    ↓ （结论）
LAB = 一面镜子，使不可见变为可见
```

## L### 五、材料使用方式

1. **人物角色作为贯穿始终的叙事装置**："Hans"不仅是分析工具，更是案例叙事的"主角"——通过Hans的故事使政府服务的抽象问题变得具体

2. **LAB作为方法论的空间化体现**：客户旅程实验室不仅是一个"地方"，更是一种"方法论的空间化"——将墙壁变为信息和工作成果的展示面

3. **逐层构建作为展示方法**：情感旅程地图的构建被描述为一个"逐层添加"的过程，使读者可以追踪分析的深度如何逐步增加

## L### 六、论辩与阐述方法

1. **"镜子"隐喻**：最终声明中的"LAB builds a mirror"——这个隐喻同时传达了三个信息：(1) 反映了现状（使问题可见）；(2) 反映了顾客（使组织看到自己如何被公民感知）；(3) 非评判性的（镜子不判断，只是反映）

2. **人物角色驱动的叙事**：案例不以"方法"开篇，而以"人物"开篇——这本身就是在实践"以用户为中心"的原则

3. **从抽象到具体到抽象**：背景（抽象问题）→ 方法实施（具体操作）→ 最终声明（抽象反思）——构成了一个完整的认知循环

## L### 九、与前后章关联

### 与前章（Ch13/实施工具）的关联
本章案例使用了Ch11-13中的多种工具（人物角色、客户旅程地图、共同创造工作坊），将这些工具从"理论上有用"的状态转变为"实践中已验证"的状态。

### 与后章（Ch15/Mypolice）的关联
NL Agency和Mypolice都属于"公共服务"领域的案例——前者处理的是"服务碎片化"问题，后者处理的是"警民信任"问题——两个案例共同展示了服务设计在公共部门的应用广度。

### 与Ch01（五项原则）的关联
本案例几乎体现了全部五项原则：以用户为中心（Persona Hans）、共同创造（与客户一起开发）、序列化（客户旅程地图）、物证化（LAB中的可视化墙壁）、整体性（跨部门整合视角）。

### 与Ch04（产品设计/服务设计）的关联
NL Agency的"交叉部门服务"问题体现了Ch04中讨论的"产品-服务系统"的挑战——政府服务是一种"纯服务"（几乎没有物理产品），它的"界面"不是ATM机而是柜台、电话和网站。
