# Ch02 分析报告：How we really use the Web（我们到底怎么用 Web）

## 章节定位与功能（行号范围）

第二章（L575-712），副题"SCANNING, SATISFICING, AND MUDDLING THROUGH（扫描、满足性选择与摸索前进）"（L577）。属第一部"指导原则"。功能：以经验观察推翻"用户是理性的精读读者"这一设计者默认假设，确立全书关于用户行为的三大"生活事实"，为后续"为扫描而设计"（Ch3）与"无脑选择"（Ch4）提供行为学依据。

## 结构分析

- 引子：儿童谜语"东西总在最后才找到，因为找到就停手"（L579-581）
- 理念落差：设计者以为用户"细读深思"，现实是"瞄一眼→扫→点第一个像样的链接"（L583-598）
- 事实 #1：我们不读页面，只扫描（L602-624）
- 事实 #2：我们不做最优选择，而是满足性选择 satisficing（L626-656）
- 事实 #3：我们不搞清楚机制，而是摸索前进 muddling through（L658-703）
- 柠檬结论：既然观众像看广告牌，就设计伟大的广告牌（L705-711）

## 内容分析

三大"生活事实"各有成因：
- **扫描**：我们"在执行任务"（像鲨鱼必须不停游动，L610）；知道不必读所有（L612）；扫描是基本功（从小读报纸杂志，年轻人刷 reddit/Tumblr/Facebook，L614）。作者用 Gary Larson《Far Side》"blah blah GINGER"漫画比喻：我们只捕捉与任务、兴趣、本能触发词（"Free"、"Sale"、"Sex"）匹配的字眼（L616-624）。
- **满足性选择**：Herbert Simon 创词（《Models of Man》，1957，L632）；Gary Klein 对消防指挥员的研究证明高压力下人们取"第一个合理方案"而非比较备选（L634-642）。Web 上此策略高效，因为：赶时间（"优化很难且费时，满足更高效"，L646）；猜错代价小（返回键是浏览器最常用的按钮，L648）；权衡未必提高命中率（L650）；猜更有趣（L652）。
- **摸索前进**：几乎没人读说明书，而是"编一个大致可信的故事"解释自己在做什么（L662-663）；《王子与贫儿》中穷孩子把英格兰国玺当核桃夹（L664-671）——用户能用错法把事办成。多数人不觉得理解机制重要（"不关智商，只关在乎"，L683）；一旦找到能用的方法就坚持下去（L687）。作者警告：设计师第一次看用户乱点时震惊，第二次想喊"点 Software 啊！"，第三次想放弃（L689-691）；但"get it"仍值得追求，因为摸索效率低、易错（L693-703）。

## 逻辑梳理

从"我们怎样用"推出"我们为什么这样用"，再推出"设计者该怎么办"。关键逻辑环：用户行为是任务驱动+低投入的 → 页面必须在极短时间内完成沟通 → 因此要按"广告牌"标准设计 → 具体技法在第 3 章展开。作者特意给出反例（用户也会权衡，取决于心境/时间/对站的信心，L654-656），避免绝对化。

## 材料使用方式

- 行为学研究：Herbert Simon 术语出处（L632）；Gary Klein《Sources of Power》对消防指挥员/飞行员/棋手/核电站操作员的观察（L634-642）
- 漫画类比：Far Side"blah blah GINGER"（L616-624）；《王子与贫儿》插图版（L664-671）
- 真实案例：biztravel.com 首页"我只想买票/查里程"的眼动式示意（L620-622）；第一次可用性测试中用户绕开"Software"点"Cheap Stuff"的实录（L689）
- 现实人物闲笔：Mark Zuckerberg、Sergey Brin 也有摸索着用的技术（L679）
- 脚注：很多人以为"Google 就是互联网"（L677）

## 论辩与阐述方法

"反常识-举证-归因-转建议"结构：先树靶（设计者想象的用户），再用研究与观察推翻，再解释行为成因，最后把"坏消息"转成设计处方。论证上大量使用权威研究（Klein、Simon）与经验观察互证；用"鲨鱼""狗狗听人话""核桃夹国玺"等强比喻降低理解成本。
