# 《现当代设计史》第十三章写作内容框架

章题：第十三章　网络、交互与信息社会中的设计。
依据：对话上传的修订版目录，以及第四至十二章已形成的写作体例。本章为内容规划，案例的选择不等于原始史料已逐项核验。各节先列时段、论点与接口，再以七个维度检查案例；设计师身份融入具体项目，不另列职业身份表。不编排详细小结、自然段或字数，不设“待补与待核”栏目。

## 一、全章定位

历史问题：当数字媒介从制作工具变为日常生活的环境，设计怎样从安排页面与产品形态，转向组织信息、行动、服务和人与平台的关系。

主体范围：1980年代至2010年代中期。界面设计保留1970年代研究的必要前史；网络与信息架构以1990年代为重心；移动与平台以2000年代后期至2010年代中期为重心。算法治理、当代平台伦理与人工智能问题交给第十四章，不以较晚的议题解释全部早期实践。

结构：13.1写媒介转变；13.2写界面与操作；13.3写信息分类、导航和标识；13.4写数据的视觉表达与交互探索；13.5写用户研究、体验和服务组织；13.6写移动情境与平台协调。中国栏写本地互联网产品与平台的形成，观念栏综合“以用户为中心”的意义及其限度。

与第十二章的关系：第十二章讲设计的数字生产工具，本章讲数字环境中的使用关系。软件可以同时属于两章，但不能重复同一发布史；需要分别回答“怎样制作”和“怎样使用”。

七个维度：作品／产品／元素／材料与技术／生产组织与设计媒介／委托与使用／观念与话语。界面、流程、地图、原型与服务蓝图可以成为作品对象，不为沿用实体产品体例而虚构材料或量产案例。

## 二、各节写作框架

### 13.1 印刷媒介向数字媒介的转变

| 项目 | 写作规定 |
|---|---|
| 时段 | 1989年至2000年代中期，以早期万维网与网站发展为主体。 |
| 论点 | 数字媒介不是纸页的简单电子化，超链接、更新机制与不同设备的显示条件改变了阅读和编辑的组织方式。 |
| 接口 | 桌面出版与数字字体归12.2、12.3；网站分类和检索归13.3；社交媒体文化归14.2。 |

| 维度 | 写作案例内容 |
|---|---|
| 作品 | CERN早期网页、Mosaic浏览器、早期报刊网站与网络杂志。比较纸本与对应网页怎样处理文章层级、链接、索引和更新，不把各类网站视为同一发展阶段。 |
| 产品 | 浏览器与在线出版服务；以HotWired等早期网络出版案例讨论内容、导航和商业展示怎样组合，不展开全部互联网企业史。 |
| 元素 | 超链接、可滚动页面、导航条、横幅广告、屏幕文字和多媒体；说明连续浏览与跳转阅读的差异。 |
| 材料与技术 | HTML、浏览器渲染、带宽与屏幕尺寸，随后加入CSS带来的内容与表现分离；技术只在解释设计限制时出现，不列版本年表。 |
| 生产组织与设计媒介 | 编辑、设计师、程序员与站点管理者的协作；网页设计从平面部门的附属任务转为独立岗位。以站点制作与更新流程交代身份分工。 |
| 委托与使用 | 科研机构、新闻出版机构、广告主与不同连接条件下的读者；线上传播扩大范围，但不能据此推定所有人拥有相同访问条件。 |
| 观念与话语 | 伯纳斯—李关于万维网的提案与论述、早期网络出版者的编辑主张；区分网络的开放理想与商业站点的经营条件。 |

### 13.2 界面设计与交互设计

| 项目 | 写作规定 |
|---|---|
| 时段 | 1970年代前史至2000年代中期，以图形界面的应用与交互方法为重心。 |
| 论点 | 界面设计把操作、反馈、错误恢复与理解方式变为设计对象，不能只以图标是否美观评价。 |
| 接口 | Alto、Macintosh的工具史归12.1；移动触控归13.6；用户研究的组织方法归13.5。 |

| 维度 | 写作案例内容 |
|---|---|
| 作品 | Xerox Star与Macintosh界面比较，苏珊·凯尔图标，Windows桌面操作；以选择文件、移动对象、删除及恢复等具体任务展开，不重复硬件发布史。 |
| 产品 | 桌面操作系统及应用界面；Palm等手持设备作为桌面隐喻受限时的比较，不写成智能手机的必然前身。 |
| 元素 | 窗口、菜单、指针、图标、对话框、状态反馈与撤销；解释隐喻、可发现性与一致性，区分外观一致和行为一致。 |
| 材料与技术 | 鼠标、键盘、显示器与早期触笔；输入方式和计算性能如何限定响应与反馈。 |
| 生产组织与设计媒介 | 界面规范、任务流程、原型和可用性测试；软件公司的设计师、交互研究者与开发人员在项目中的不同职责。 |
| 委托与使用 | 软件企业、初学者与熟练使用者、不同感知和运动能力的使用者；可访问性不能只在完工后作为附加检查。 |
| 观念与话语 | 施奈德曼关于直接操作的论述、诺曼《日常事物的设计》、莫格里奇《设计交互》。可供性与能指等术语应对应具体版本，不把后出的修订当作早期原话。 |

### 13.3 信息设计与信息架构

| 项目 | 写作规定 |
|---|---|
| 时段 | 1970年代必要前史至2010年前后，以网络信息架构为主体。 |
| 论点 | 信息设计不仅使内容可见，更通过命名、分类、导航和检索决定使用者能否找到并理解信息。 |
| 接口 | 战时ISOTYPE与识别手册归8.3，瑞士网格归9.4；数据表达归13.4；服务流程归13.5。 |

| 维度 | 写作案例内容 |
|---|---|
| 作品 | 沃尔曼的信息表达与《信息焦虑》作为前史；Yahoo目录与检索型网站对照；大型图书馆、博物馆或政府网站的信息结构作为主体案例。 |
| 产品 | 网站目录、搜索结果页、站点地图、公共信息服务；不把纸本信息图全部移入本节。 |
| 元素 | 分类、标签、面包屑、导航层级、搜索与筛选；说明信息架构和可见页面布局不是同一层面。 |
| 材料与技术 | 数据库、索引、元数据和内容管理系统；技术结构与使用者理解之间可能发生冲突。 |
| 生产组织与设计媒介 | 卡片分类、内容清单、树形结构、线框图；信息架构师与编辑、图书情报专业人员、开发者的协作。 |
| 委托与使用 | 公共机构、商业站点与具有不同知识背景的访问者；内部部门结构不能直接等同于用户需要的导航结构。 |
| 观念与话语 | 沃尔曼相关论述、罗森菲尔德与莫维尔《万维网信息架构》。文本用于解释分类和导航的方法，不把“信息架构”追溯成单一人的完整发明。 |

### 13.4 数字时代的数据可视化

| 项目 | 写作规定 |
|---|---|
| 时段 | 1980年代方法前史至2010年代中期。 |
| 论点 | 数据可视化把图表从静态说明转为交互探索，但编码、尺度和数据来源依然决定其解释能力及误导风险。 |
| 接口 | 信息分类归13.3；算法数据与当代治理归14.3；不重复第一章统计图表的一般前史。 |

| 维度 | 写作案例内容 |
|---|---|
| 作品 | Gapminder趋势图、纽约时报交互新闻图表、Processing与D3相关项目；按明确的数据集、任务和交互方式选择作品，而非用软件名代替作品分析。 |
| 产品 | 交互图表、数据地图、仪表盘与可视化工具；新闻、科研和经营监测分别选择有限案例，不堆砌全部类型。 |
| 元素 | 位置、长度、面积、色彩与时间编码；悬停、筛选、缩放、联动视图；区分装饰性动效和有助理解的变化。 |
| 材料与技术 | 数据清理、浏览器图形、脚本与可视化库；缺失值、来源与更新周期也是设计条件。 |
| 生产组织与设计媒介 | 记者、数据分析人员、程序员与视觉设计师组成的团队；草图、代码、数据字典和测试共同参与生产。 |
| 委托与使用 | 新闻读者、科研人员、管理者与公共政策受众；不能把易读性等同于统计推论的有效性。 |
| 观念与话语 | 塔夫特的定量信息表达著述、伯廷等视觉研究的必要前史、交互可视化项目的方法说明。比较静态表达与探索性界面，不以单一审美原则评价全部图表。 |

### 13.5 用户体验与服务设计

| 项目 | 写作规定 |
|---|---|
| 时段 | 1980年代服务方法前史至2010年代中期。 |
| 论点 | 设计对象从单次操作扩展为跨时间、跨接触点的体验与服务，用户研究也从产品检验转为组织决策的一部分。 |
| 接口 | IDEO组织史归11.2、设计思维传播归11.4；本节写研究与服务流程，平台多方关系归13.6。 |

| 维度 | 写作案例内容 |
|---|---|
| 作品 | 诺曼在苹果时期的用户体验岗位与团队作为组织案例；IDEO购物车实验作为研究流程案例，不冒称已全面量产；英国公共服务的设计改进项目选一件有完整项目材料者展开。 |
| 产品 | 预约、就诊、银行或公共办事服务中的跨渠道流程；实体产品、网站、工作人员与后台系统共同构成服务，不把服务只写成应用界面。 |
| 元素 | 用户旅程、接触点、等待、反馈、交接与异常处理；区分实际使用者、购买者、服务人员与管理方。 |
| 材料与技术 | 研究记录、访谈、观察、原型与服务演练；数字后台与实体空间共同限定服务实施。 |
| 生产组织与设计媒介 | 人物角色、旅程图、服务蓝图与共同设计；用户体验研究者、服务设计师、运营者与一线人员的职责随项目交代。人物角色不是未经研究的想象画像。 |
| 委托与使用 | 企业、公共机构、顾客与服务工作人员；委托方的效率指标可能与使用者的体验目标冲突。 |
| 观念与话语 | 肖斯塔克关于服务蓝图的论述、加勒特《用户体验要素》、以人为中心设计相关标准。区分用户体验、可用性与服务设计，不合并成单一方法。 |

### 13.6 移动互联网与平台设计

| 项目 | 写作规定 |
|---|---|
| 时段 | 2000年代至2010年代中期。 |
| 论点 | 移动设备使服务随情境变化，平台把设计任务扩展到多方参与者、规则和交易；界面方便不意味着所有参与者均受益。 |
| 接口 | iPod与数字硬件归12.5；社交媒体文化归14.2，算法治理与伦理归14.3、14.6。 |

| 维度 | 写作案例内容 |
|---|---|
| 作品 | iPhone与App Store、Android生态、地图导航与移动出行服务；选择司机端与乘客端对应任务分析，不只展示消费者首页。 |
| 产品 | 移动应用、应用商店、位置服务、平台交易与评价系统；通知、支付和账号成为不同服务的连接条件。 |
| 元素 | 多点触控、手势、定位、列表与卡片、状态通知、评分与信任提示；说明小屏幕和移动情境如何改变信息优先级。 |
| 材料与技术 | 触摸屏、GPS、移动通信、传感器、API；只讨论与设计直接相关的条件，不列全部手机技术代际。 |
| 生产组织与设计媒介 | 平台设计规范、开发者工具、产品团队与持续迭代；设计师与产品经理、工程师、数据分析者、运营者协作。实验指标不自动等于用户利益。 |
| 委托与使用 | 平台企业、消费者、商家、劳动者与开发者；把多边参与关系写清，不将全部参与者统称为“用户”后抹去差异。 |
| 观念与话语 | 苹果与Android界面规范、移动设计方法与平台服务的规则文本；区分企业的体验承诺和实际的分配机制，后者的当代伦理分析归第十四章。 |

### 中国：互联网产品与平台设计

| 项目 | 写作规定 |
|---|---|
| 时段 | 1990年代至2010年代中期。 |
| 论点 | 本地互联网设计在门户、即时通信、电子商务与移动服务中形成，中文阅读、支付条件和社会交往方式参与塑造产品，而非仅复制海外界面。 |
| 接口 | 汉字照排与字库归第十二章中国栏；本节写中文网络的阅读与操作；更晚的平台治理和“中国设计”政策归第十四章。 |

| 维度 | 写作案例内容 |
|---|---|
| 作品 | 门户首页、QQ即时通信、淘宝与支付宝、微信；选具有明确版本记录的界面或流程作比较，不把今天的功能写回初版。 |
| 产品 | 门户资讯、聊天客户端、电商交易、第三方支付、公众号与移动支付；按阶段说明连接、交易和服务如何逐步结合。 |
| 元素 | 中文信息密度、分类导航、表情与头像、在线状态、交易信用、聊天入口与二维码；不能把所谓“高密度”解释为全部中国用户的固定偏好。 |
| 材料与技术 | 中文编码与浏览器显示、宽带和移动接入、账号体系、支付与二维码；字库技术本身回指第十二章。 |
| 生产组织与设计媒介 | 企业用户研究与体验部门、产品团队、设计规范和跨端协作；设计者从网页美工转向交互、视觉、研究等分工的变化结合实际团队资料交代，不规定统一职业接力。 |
| 委托与使用 | 平台企业、个人、商家、支付机构与开发者；城乡、设备与使用经验的差异作为项目条件。 |
| 观念与话语 | 企业设计团队的项目记录、设计规范与用户研究材料；把“以用户为中心”作为需要检验的主张，不直接视为实际成果。 |

### 观念：以用户为中心的设计

| 项目 | 写作内容 |
|---|---|
| 核心问题 | “用户”如何进入设计决策，谁被纳入研究，谁的利益没有被这一称谓充分表达？ |
| 分析材料 | 13.2操作与可用性，13.3分类与理解，13.4数据解释，13.5研究与服务，13.6平台多方关系，以及中国栏的本地产品实践。 |
| 分析任务 | 区分以用户为中心与以人为中心的使用语境；分析观察、测试、参与和量化指标各能回答什么问题。讨论使用者、购买者、劳动者与非使用者的不同位置。 |
| 表述限制 | 不把用户研究写成能消除所有冲突的科学方法；不把点击率、留存率与满意度自动等同；不把数字产品的便利推定为普遍可访问。 |
| 与正文分工 | 正文说明项目如何完成，观念栏综合其决策与权力关系；不机械规定正文只能引用、章末才能分析。 |
| 接口 | 接第十二章职业重组，向第十四章数据、算法、人工智能与设计伦理开放。 |

## 四、图像材料选择

13.1：早期网页与纸本对应版面；13.2：具体任务的界面序列与图标；13.3：分类树、导航与搜索结果；13.4：具有数据说明的交互图表；13.5：旅程图与服务蓝图；13.6：移动端操作与平台多方流程；中国栏：门户、QQ、淘宝、微信的有日期记录的版本对照。

配图需标明版本、时间、任务和出处。流程图应区分研究者重绘与项目原图，不把功能示意当作实际历史界面。

## 五、编写依据方向

万维网与浏览器采用CERN、W3C及相关档案；界面采用施乐、苹果档案与人机交互原始研究；信息架构采用相关著述及项目材料；数据可视化采用项目数据说明和开发文献；服务设计采用服务蓝图原始论文、标准及机构项目报告；移动平台采用有日期的设计规范与开发文档；中国栏目采用企业历史版本、设计团队项目资料及公开研究。

所有版本、年份、原话与效果指标在正文编写时对应具体出处。框架中的例子是对象选择，不宣称相关企业的全部用户研究或内部决策已被公开证实。
